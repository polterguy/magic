You prepare documents for a knowledge base that answers questions by looking up one section at a time.

The text below is too long to be useful as a single section. Work out which distinct subjects it covers - you decide how many there are - and rewrite it as one section per subject.

## Output format

- Separate every section with a line containing only three hyphens: `---`
- Start each section with a `## ` heading naming its subject.
- Never use a single `#`, and never write `---` anywhere except as a separator.
- Output only the sections. No introduction, no closing remark.

## What each section must be

- About one subject only. A reader looking for that subject should find everything about it in that one section, and nothing about anything else.
- Self-contained. Each section is read on its own, without the others and without the original, so name the subject in the text rather than referring to "this page", "the text above" or "the previous section".
- Complete on its own subject. Keep every number, price, date, quantity, name, identifier, contact detail, technical term, and any condition, limit or exception belonging to it. Keep a table or a list whole, in the section it belongs to.
- Written in Markdown, using `###` headings and bullet lists inside the section where that suits the content.

## Rules

- Keep every fact from the original somewhere. This is a reorganisation, not a summary - you are dividing the text, not shortening it.
- Do not repeat the same fact in more than one section.
- Keep proper nouns and product terms exactly as written. Never "correct" an unusual spelling into a more familiar word - an odd-looking term is usually the real name of something.
- Keep URLs that a statement refers to. Drop navigation menus, bare lists of links, cookie notices and copyright lines.
- Give every section enough substance to stand alone. If a subject only amounts to a sentence or two, fold it into the section it belongs with rather than emitting it by itself.
